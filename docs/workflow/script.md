# Workflow разработки с AI-агентом

## Главный принцип

Разработка выполняется последовательно, этап за этапом.

---

# 0.0 Контекст

Изучи сначала:

* Wiki;
* Context.

Потом изучи:

* существующие похожие сервисы;
* proto-контракты;
* связанные тесты;
* существующие архитектурные паттерны.

Предоставь понимание текущей архитектуры.

В конце отдельно перечисли вопросы, требующие моего решения.

---

# 0.1 ТЗ

Изучи:

* требования задачи;
* issue, если есть.

Предоставь:

* понимание задачи;
* существующие реализации, которые следует переиспользовать;
* применяемые архитектурные паттерны;
* потенциально релевантные файлы;
* найденные противоречия;
* неопределённости и вопросы.

В конце отдельно перечисли вопросы, требующие моего решения.

---

# 1. Понимание задачи

Сформулируй техническое понимание задачи.

Опиши:

* ответственность нового функционала;
* входные данные;
* выходные данные;
* основные сценарии;
* ограничения;
* зависимости;
* ошибки;
* взаимодействие с другими сервисами;
* ожидаемое поведение.

В конце отдельно перечисли вопросы, требующие моего решения.

---

# 2. Алгоритм / бизнес-логика

Опиши подробный алгоритм работы функционала.

Для каждого основного сценария укажи:

* последовательность действий;
* входные данные;
* проверки;
* изменения состояния;
* взаимодействие с внешними сервисами;
* ошибки;
* граничные случаи;
* ожидаемый результат.

Все неопределённости вынеси в отдельные вопросы.

---

# 3. Структура файлов

Предложи структуру реализации.

В качестве основного reference используй существующие похожие сервисы.

Покажи дерево:

```text
service/
├── ...
├── ...
└── ...
```

Для каждого файла кратко укажи его ответственность.

---

# 4. Реализация

Реализуй только согласованные:

* proto;
* алгоритм;
* структуру файлов;
* архитектурные решения.

После реализации выполни:

* typecheck;
* build;
* необходимые проверки проекта.

Предоставь:

* созданные файлы;
* изменённые файлы;
* удалённые файлы, если есть;
* результат typecheck;
* результат build;
* оставшиеся проблемы.

Остановись.

---

# 5. Тесты бизнес-логики

Предложи unit-тесты на основании созданного кода.

Для каждого тестового файла укажи:

* путь;
* назначение;
* сценарии;
* ожидаемые результаты;
* edge cases.

Тесты должны покрывать:

* успешные сценарии;
* валидацию;
* ошибки;
* граничные условия;
* важные edge cases.
