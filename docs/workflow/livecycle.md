# Lifecycle тикета

Доска проекта: https://github.com/users/beartrando/projects/2 — GitHub Project `beartrando` #2.

Используемые колонки: `Todo`, `In Progress`, `Clarification`, `Review`.

DevOrc работает только с тикетами, находящимися в колонке `Todo` доски проекта.

Анализ задачи можно проводить без тикета. Изменения вносятся только при наличии тикета: если тикета нет, его необходимо создать на главной доске в колонке `Todo` и далее работать по описанному ниже флоу.

## Получение тикета

При выборе следующей задачи DevOrc:

1. Находит тикет в колонке `Todo`.
2. Первым действием помещает тикет в `In Progress` и приступает к работе.
3. Загружает контекст тикета.
4. Восстанавливает рабочий контекст перед началом итерации.

## Контекст тикета

Context-репозиторий является основным контейнером контекста конкретной задачи.

Также необходимо максимально коротко вести контекст в тикете.

## Итерации

Работа над тикетом может состоять из нескольких итераций.

Каждая итерация должна:

1. Выполнить очередную часть работы.
2. Определить следующее состояние тикета.

## Завершение задачи

Если задача полностью реализована:

1. Убедиться, что все необходимые изменения проверены.
2. Создать Pull Request'ы в `dev`.
3. Добавить ссылки на Pull Request'ы в тикет.
4. Перевести тикет в `Review`.

## Clarification

Если возникают вопросы по тикету:

1. Опубликовать вопросы в тикете.
2. Перевести тикет в колонку `Clarification`.
3. Завершить работу над тикетом.

## Создание нового тикета

При создании нового тикета соблюдайте следующие правила:

- **Колонка**: Тикет должен создаваться в колонке `Todo` или `In Progress`
- **Название**: Указать четкое название задачи
- **Описание**: С кратким описанием задачи и критериями завершения

После создания тикета первым действием поместите его в колонку `In Progress`, если вы сразу приступаете к работе, или оставьте в `Todo`, если нужно время на планирование.
